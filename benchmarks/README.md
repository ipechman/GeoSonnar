# Validation and research

For current software checks, start with the [public development tools](../tools/README.md), [contributor guide](../CONTRIBUTING.md) and [test map](../tests/README.md). These distinguish ordinary checks, synthetic media integrations, optional external inputs and release packaging.

This directory also contains frozen scientific protocols, upstream mappings and research harness controls. The historical full-recording runner requires separately acquired data and is not the default contributor workflow.

| Record | Scope |
| --- | --- |
| [Historical validation](HISTORICAL_VALIDATION.md) | Older application releases, numerical baselines, local receipt paths and interpretation limits. |
| [Hybrid ablation](HYBRID_ABLATION.md) | Synthetic Doppler/thunder modality comparisons and misleading alternatives. |
| [Discovery](DISCOVERY.md) | Detection methodology and the separately acquired recording corpus. |
| [Reviewed search](REVIEWED_SEARCH.md) | Transfer of reviewed proposals into the matcher. |
| [Audio priors](AUDIO_PRIORS.md) | Audio-derived search assumptions and sensitivity. |

Software checks establish behavior on declared inputs. Independent location accuracy, provider coverage and worldwide performance require separate evidence; a static catalog or historical pass does not establish a current result.
